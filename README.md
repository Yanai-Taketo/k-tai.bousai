# k-tai.bousai — 文字中心・軽量防災サイト構想

通信環境が悪い場所や輻輳した環境でも読める、旧来のケータイサイトのような**文字中心の軽量防災サイト**をつくるプロジェクト。

地図タイルや大量のJavaScriptに依存する近年の防災サイトは、災害時のアクセス集中・低速回線・応急復旧された細い回線の下で実用にならないことがある。本プロジェクトは、数KB〜数十KB級のテキストページで防災情報を届けることの実現性を検証し、設計・制作・テスト・公開までを目指す。

生命に関わる情報を扱うため、**一次情報(政府機関・気象庁・通信キャリア等の公式発表)の確認を必須**とする方針で進めている。

### 調査結論の要旨(第2次まで反映)

- **総合判断: 条件付きGO**。「輻輳でサーバが落ちる時の避難サイト」ではなく「**低速・劣化した回線でも開ける、平時から使える気象・地震情報の確認と公式リンクの場**」として、存在意義・実現性ともに立証された。
- **需要側**: 災害時にWebを自分から見に行く行動は実在(平時想定でHP閲覧58.8%で2位・年代差最小。生活・行政情報フェーズでは自治体HPが主要手段に浮上)。ただし発災直後の速報はテレビ・アプリ・SNSが支配し、本サイトは「第一想起メディア」ではない。
- **2024年以降**: 輻輳による公的サイトのダウンは確認できないが、DDoS・CDN障害・システム障害・自治体側被災と障害モードは多様化。公式サイトは重量化が進み(気象庁防災トップgzip約250KB等)、軽量な受け皿はむしろ消滅した。
- **避難情報**: 個人が機械可読で入手する正規の道は**ない(黒で確定)**。静的避難場所データ+自治体リンク誘導で設計し、2026年12月のLアラート総務省移管後の新規約公表を再評価トリガーとする。
- **競合**: 数KB級の日本語テキスト防災Webは個人・OSS・商用に不在(空白確定)。
- **到達経路**: 「作っても発見されない」リスクは深刻。平時の日常価値・ホーム画面追加導線・OSS公開を**機能要件**として設計に含める。
- **運用**: さくらVPS+異系統無料CDN2系統(Cloudflare Pages+GitHub Pages)で月1,000〜2,000円台の現実解。気象庁フィードはPULL型のみ(WebSubは2020年終了)・毎分取得でも月約2GB。

次フェーズ(要件定義・設計)は、第2次報告書「12. 依頼者に相談すべき論点」の合意後に着手する。
