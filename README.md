# k-tai.bousai — 文字だけの軽量防災情報サイト

気象庁の防災情報を、**1ページ2KB前後の文字だけのページ**として配信します。
速度制限のかかったスマートフォンや、災害で細くなった回線でも開けることを目的にしています。

**公開中**

- https://k-tai-bousai.pages.dev (主系: Cloudflare Pages)
- https://yanai-taketo.github.io/k-tai.bousai (副系: GitHub Pages)

同じ内容を独立した2系統で配信しています。片方が落ちても、もう片方が生きています。

> 本サイトは気象庁の公式サイトではなく、個人が運営しています。
> 避難や身を守る行動の判断は、必ずお住まいの自治体・気象庁の発表に従ってください。

## なぜ作るのか

近年の防災サイトは地図タイルと大量のJavaScriptに依存しており、平時は快適でも、
**回線が細いときや混雑しているときほど開けなくなる**という弱点があります
(気象庁の防災トップページはgzip後で約250KB)。

一方、2019年の台風19号では国土交通省が「川の防災情報 簡易版」を緊急提供して急場をしのぎ、
東京都は区市町村向けガイドラインで非常時コンテンツを「テキスト主体の軽量なページ」で
用意するよう求めています。**軽量な受け皿には実績と公的な裏付けがあります**が、
調査した限り数KB級の日本語テキスト防災サイトは現存しませんでした
([第1次調査](docs/research/2026-08-13-feasibility-report.md) /
[第2次調査](docs/research/2026-08-14-supplementary-report.md))。

## 掲載している情報

すべて気象庁の発表を**そのまま**掲載します。独自の予報・加工はしません。

| 情報 | ページ | 電文 |
|---|---|---|
| 気象警報・注意報 | 府県ページ | VPWW55〜61(2026年5月開始の新体系) |
| 指定河川の洪水予報 | 府県ページ | VXKO50〜76 |
| 熱中症警戒アラート | 府県ページ | VPFT50 |
| 気象防災速報(記録的短時間大雨・線状降水帯・竜巻) | 府県ページ | VPBS50 / VPHW50・51 |
| 天気予報・週間天気予報 | 府県ページ | VPFD51 / VPFW50 |
| 地震(一覧+各地の震度) | `/eq` | VXSE51 / VXSE53 |
| 津波 | `/tsunami` | VTSE41 |
| 台風 | `/typhoon` | VPTW60〜65 |

一部は気象庁単独の発表ではないため、発表主体をそのまま表示します
(熱中症警戒アラート=環境省・気象庁、指定河川洪水予報=河川管理者・気象庁)。

**掲載していないもの**: 避難指示・避難所の開設状況。個人が機械可読で入手できる
公式経路が存在しないためです([調査で確定](docs/research/2026-08-14-supplementary-report.md))。
避難に関する情報は自治体の発表・緊急速報メール・テレビ・ラジオで確認してください。

## 実測値

**ページサイズ**(73ページ・gzip後)

| ページ | 最大 |
|---|---|
| 府県(58ページ) | 2,218 B |
| 地震詳細(10ページ) | 2,454 B |
| トップ | 2,178 B |
| 地震一覧 / 台風 / 津波 | 1,623 / 1,506 / 1,223 B |

**128kbps・往復遅延300msでの表示完了時間**
(`prototype/measure/measure-site.mjs` で計測。ローカル配信のため非圧縮=実環境より不利な条件)

| ページ | 表示完了 | 転送量(非圧縮) |
|---|---|---|
| 府県(東京) | 754 ms | 6.9 KB |
| このサイトについて | 665 ms | 5.3 KB |
| トップ | 659 ms | 5.8 KB |
| 地震詳細 | 595 ms | 3.5 KB |
| 台風 | 586 ms | 3.2 KB |
| 津波 | 489 ms | 2.7 KB |

**更新の実績**: 反映間隔の中央値3分・最大11分、直近40実行で失敗0件。

## 仕組み

```
気象庁 防災情報XML(無償フィード)
        │
        │ ① Cloudflare Workers Cron(毎分)
        │    最新電文の時刻 > 前回ビルド開始時刻 なら起動
        │    + 10分以上更新がなければ無条件起動(更新間隔の上限保証)
        ▼
   GitHub Actions ── generator/(Python標準ライブラリのみ)
        │              フィードから現在有効な電文集合を毎回まるごと再構築
        │              (差分を持たないので取りこぼしも二重処理も起きない)
        ├──▶ Cloudflare Pages(主系)
        └──▶ GitHub Pages(副系)
```

- **JavaScript・画像・Webフォントを一切使いません。** CSSは全ページ共通の約1KBをインライン化。
- 内部リンクは拡張子なし(`/p/130000`)。両ホストともリダイレクトなしで配信されます。
- 巨大地震で震度の観測地点が数千件になる場合は、市町村→地域→都道府県と粒度を自動的に
  落としてページ予算内に収めます(縮約したことはページ上に明示)。
- 15分ごとに死活・鮮度を監視し、異常時はIssueを自動起票します。

## 開発

Python 3.11以上。**依存パッケージはありません**(標準ライブラリのみ)。

```bash
# サイトを生成(site/ に出力)
python3 -m generator.main

# テスト(実電文フィクスチャによるゴールデンテスト 53件)
python3 -m unittest discover -s tests

# トリガー判定ロジックのテスト(6件)
cd worker && node --test

# 128kbps低速回線での表示時間を計測
python3 -m generator.main --site /tmp/site
(cd /tmp/site && python3 -m http.server 8123 &)
cd prototype/measure && node measure-site.mjs
```

生成物はリポジトリにコミットしません(履歴の肥大化を避けるため)。

## リポジトリ構成

```
generator/            サイト生成(Python標準ライブラリのみ)
  main.py               フィード取得→解析→ページ生成のエントリポイント
  parse_*.py            電文種別ごとの解析(警報/地震・津波/天気/速報/台風/洪水/熱中症)
  render.py             HTML生成(インラインCSS・JSなし)
  offices.py            官署テーブルと地方順の並び
tests/                実電文フィクスチャによるゴールデンテスト
worker/               Cloudflare Workers 毎分トリガー(+判定ロジックのテスト)
tools/monitor.py      死活・鮮度監視
.github/workflows/    build-deploy.yml / fallback-schedule.yml / monitor.yml
docs/
  setup.md              公開セットアップ手順
  requirements.md       要件定義書
  design.md             設計書
  decisions.md          意思決定記録
  mockups/              レイアウト検討用モック
  research/             調査報告書(下記)
prototype/            フェーズ0の実証コードと128kbps計測ハーネス(参照用)
```
