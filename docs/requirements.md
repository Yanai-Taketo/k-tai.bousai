# 要件定義書 — 文字中心・軽量防災サイト(フェーズ1)

- 作成日: 2026-08-14
- 根拠: 第1次・第2次調査報告書([docs/research/](research/))および意思決定記録([decisions.md](decisions.md) #1〜#15)
- 位置づけ: フェーズ1(初回公開)の要件を定める。本書の各要件は決定番号(#n)に紐づく。

## 1. 目的・ポジショニング(#2, #9)

通信環境が悪い場所・輻輳した環境・**通信速度制限(ギガ超過後の128kbps級)下**でも開ける、文字中心の軽量防災情報サイト。

- 本サイトは**公式情報の補完**である。エリアメール・テレビ・radiko・公式アプリの代替ではない。
- 軽量化が効くのは「サーバ側の輻輳」「低速・不安定な回線」。**基地局停波・圏外には効かない**。この限界をサイト上でも明示する。
- 速報のプッシュ通知は行わない。「自分から見に行って状況を確認する場」に徹する。

## 2. 対象利用者(#2)

- 主対象: **低速・劣化・速度制限下の回線を使うスマートフォン利用者**。
- 副次対象: 素のHTMLが読める任意の端末(現行4Gケータイ・古いブラウザ等)。個別の実機対応保証はしないが、JS必須にしない設計で結果的に閲覧可能性を最大化する。

## 3. 機能要件(コンテンツ)

### 3.1 掲載する情報(#8, #13)— すべて気象庁防災情報XMLの「そのまま転載」

| ID | 内容 | 電文の例 | 更新契機 |
|---|---|---|---|
| F-1 | 気象警報・注意報(全国概況+府県別詳細) | 気象警報・注意報電文(新たな防災気象情報の体系に完全準拠) | フィード更新の都度 |
| F-2 | 地震情報(震度速報・震源震度に関する情報の直近N件) | VXSE51/VXSE53系 | 同上 |
| F-3 | 津波情報(津波警報・注意報・予報の現況。平時は「発表なし」を明示) | VTSE41等 | 同上 |
| F-4 | 府県天気予報(今日・明日・明後日)+週間天気予報 | VPFD5x/VPFW5x系 | 同上 |
| F-5 | サイト説明・免責・出典・限界の明示(about) | — | リリース時 |

### 3.2 掲載しない情報(#1, #8, #10)

- リアルタイム避難情報(避難指示・避難所開設)— 個人の機械可読入手経路が存在しないため(第2次調査で確定)。
- **静的な避難場所リスト・自治体リンク集** — 手動メンテナンスが必要となるため掲載対象外。
- 独自の予測・解説・注意喚起(気象業務法17条・23条対応。転載に徹する)。
- 到達支援機能(QRページ・共有ボタン等)— 機能ミニマム。周知は依頼者のブログ等で行う。

### 3.3 全ページ共通の必須表示(#5=第1次決定、第1次報告§7)

- R-1: **データ取得時刻**(「◯月◯日 ◯時◯分 取得」)を先頭付近に表示。
- R-2: 各情報の**発表主体と発表時刻**(「◯◯気象台 ◯時◯分発表」)を電文ごとに表示(独自警報との誤認防止)。
- R-3: **出典表示**「出典: 気象庁ホームページ」+当該ページへのリンク。
- R-4: フィード側の鮮度劣化を生成時に検知した場合、**劣化警告**(「気象庁からのデータ取得が◯分間更新されていません。最新は気象庁ホームページで確認してください」)をページ上部に表示。
- R-5: 非公式サイトであることの明示と、公式(気象庁・自治体)への誘導文。

## 4. 非機能要件

### 4.1 軽量性(#6, #9)

- N-1: 各ページのHTML本体は**gzip後10KB以下**を上限、通常5KB以下を目標(プロトタイプ実績: 2.5〜4.7KB)。
- N-2: 画像・Webフォント・外部CSS・外部JSを使わない。CSSは最小限のインライン(1KB程度)。
- N-3: JavaScriptなしで全機能が成立する(使う場合も装飾的な漸進的強化に限り、無くても情報が欠けない)。
- N-4: **128kbps・RTT300msのエミュレーション環境で表示完了2秒以内**(既存の計測ハーネスで検証)。

### 4.2 更新・鮮度(#3, #15)

- N-5: フィード更新から公開反映まで**目標5分以内**(機構上の見込み2〜4分)。
- N-6: 更新パイプラインが停止しても配信は継続する(静的サイトの性質)。その際、利用者にはR-1の取得時刻で鮮度が判断できること。
- N-7: フィード取得は気象庁の利用条件を遵守(PULL型・条件付きGET・1日10GBを大幅に下回る転送量)。

### 4.3 可用性(#7, #15)

- N-8: 配信は**異系統2系統**(Cloudflare Pages+GitHub Pagesミラー)へ常時同時デプロイ。
- N-9: 無料プラン(SLAなし)前提のため、数年に一度の数時間級CDN障害は許容し、2系統で緩和する。

### 4.4 運用(#4=第1次決定, #10)

- N-10: 運用は完全自動。**手動メンテナンスを要する静的データを持たない**。
- N-11: 障害(取得失敗・生成失敗・デプロイ失敗・フィード停滞)は運用者に通知される。
- N-12: 月額実費はドメイン代+α(目標: 数百円以内。ホスティング費ゼロ)。
- N-13: DMDATA(Project DM-D.S.S)への将来移行を阻害しない(取得層の差し替え可能設計、Linode追加でそのまま動く)。

### 4.5 法令・規約遵守(第1次報告§5)

- N-14: 気象庁発表の**無改変転載**に徹する(予報業務許可不要の範囲。空間内挿・独自加工をしない)。
- N-15: 気象庁利用規約に基づく出典表示。「国が作成したかのような態様」にならない表示設計。
- N-16: 2026-05-28開始「新たな防災気象情報」の名称・区分に完全準拠(#13)。旧名称の残置をしない。

## 5. 受け入れ基準(フェーズ1公開の条件)

1. 全ページがN-1〜N-4を満たすことを計測ハーネスで確認。
2. 実際のフィードからの自動更新がN-5を満たすことを1週間以上の連続運転で確認。
3. フィード監視(N-11)が実際の欠配・停滞を検知して通知することをテストで確認。
4. 警報・注意報の表示名が新体系(N-16)に一致することを気象庁ページとの突合で確認。
5. 免責・出典・取得時刻表示(R-1〜R-5)の全ページ実装。
6. 依頼者による表示内容・文言の最終確認。
