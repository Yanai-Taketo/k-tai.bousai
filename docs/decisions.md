# 意思決定記録

プロジェクトの方向性に関する依頼者の決定を記録する。設計・実装はこの決定に従う。

## 2026-08-13: 調査報告書(第1次)を受けた方針決定

第1次調査報告書(`research/2026-08-13-feasibility-report.md`)の「10. 依頼者に相談すべき論点」に対する依頼者の決定。

| # | 論点 | 決定 |
|---|------|------|
| 1 | 避難情報のスコープ | **最終調査を実施した上で、個人が機械可読で入手する道が本当にないなら諦める。** 補強調査(第2次)でLアラート移管後の見通し・代替経路を白黒つける |
| 2 | 想定利用者の優先順位 | **低速回線下のスマートフォン利用者を主対象とする。** 4Gケータイ(ガラホ)対応は主目標としない(素のHTMLで結果的に見られる分には歓迎) |
| 3 | 信頼性への投資 | **無償の気象庁防災情報XML Atomフィード(ベストエフォート・無保証)で開始する。** 将来的にDMDATA(Project DM-D.S.S)との連動を検討する |
| 4 | 次アクション | **補強調査とプロトタイプ構築・128kbps実測を並行して実施する** |

### 決定から導かれる設計上の含意

- 主対象が低速回線下のスマホであるため、ページは素のHTML+最小CSSで構成し、JavaScriptなしで全機能が成立すること(漸進的強化)。
- 無償フィード前提のため、フィード停止の機械検知(`<updated>`監視)と、全ページでのデータ取得時刻の明示・鮮度劣化時の警告表示を必須要件とする。
- DMDATA連携を将来像に置くため、データ取得層は「取得元を差し替え可能」な構造にする(フィード取得部と生成部の分離)。
- 避難情報は補強調査の結論が出るまで実装スコープに含めない。
