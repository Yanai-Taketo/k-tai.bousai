# ドメイン選定 — 推奨と根拠

- 作成日: 2026-08-15
- 位置づけ: 独自ドメインの名前・TLD・運用構成の選定。**決定は依頼者が行う**(本書は提案と根拠)。
- 関連要件: N-12(費用)、N-8/N-9(可用性)、N-15(国が作成したかのような態様にしない)、R-5(非公式である旨の明示)

> **注意(公開リポジトリのため)**: 本書は「現在取得可能な候補ドメイン名」を含む。取得すると決めた候補は
> **先に登録してから**本書を `main` に取り込むことを推奨する。候補名が公開された状態で未登録のまま置くと、
> 第三者に先に取られる余地を残す。

## 1. 結論

**推奨: `mojibosai.jp`(文字防災)**

汎用JPドメイン名。2026-08-15 の JPRS WHOIS 照会で未登録を確認[^whois]。

| 項目 | 内容 |
|---|---|
| 読み | もじぼうさい |
| 長さ | `mojibosai.jp` = 12文字(ラベル9文字)。ハイフン・数字なし |
| 意味 | 「文字だけの防災情報」= README冒頭の自己定義そのもの |
| 誤認防止 | 一般名詞に修飾語が付いた造語。気象庁・内閣府・防災科研のいずれの名称・ドメインとも衝突しない |
| 中立性 | 個人名・地域名を含まない。自治体・シビックテックへの引き継ぎを妨げない |

**任意(表記ゆれ対策)**: `mojibousai.jp` を別名として押さえ、301で `mojibosai.jp` に寄せる。
「ぼうさい」をローマ字入力の習慣どおり `bousai` と打つ利用者を取りこぼさないための保険。必須ではない。

**配信構成**(独自ドメイン導入後):

| 役割 | ホスト | ドメイン |
|---|---|---|
| 主系 | Cloudflare Pages | `mojibosai.jp`(apex)+ `www.mojibosai.jp` |
| 主系(素のURL) | Cloudflare Pages | `k-tai-bousai.pages.dev` — **そのまま残す**(既定で残る[^cfpages-redirect]) |
| 副系 | GitHub Pages | `yanai-taketo.github.io/k-tai.bousai` — **カスタムドメインを設定しない** |

副系にカスタムドメインを設定してはならない理由は §7.1(実測)。

## 2. 選定基準(要件からの導出)

| # | 基準 | 根拠 | 具体化 |
|---|---|---|---|
| C1 | 公的機関と誤認されない | N-15, R-5 | `.go.jp` は登録資格なし。`jma`/`kishou`/`japan`/`official` 等の権威を装う語を使わない。既存の公的ドメインと紛らわしい形にしない |
| C2 | 短く、打ち間違えない | 決定#2(低速回線下のスマホが主対象) | 全体13文字以内、ハイフン・数字なし、ローマ字の読みが一意 |
| C3 | サイトの本質が伝わる | 決定#6, #9 | 「文字だけ」「軽い」が想起できる |
| C4 | 到達性の読めるTLD | N-8(可用性) | `.jp`/`.com`/`.net`/`.org` に限定 |
| C5 | 単一ベンダに寄せない | N-8/N-9、第1次報告§9 | レジストラ・DNS・主系・副系のうち少なくとも1つは他系と独立させる |
| C6 | 引き継ぎ可能な中立名 | README「自治体・シビックテックによる再利用を想定」 | 個人名・地域名を含めない |
| C7 | 月数百円以内 | N-12 | 年4,000円弱まで |

ドメイン名の長さがページ転送量に与える影響は数十バイト規模で、N-1(gzip後10KB以下)に対して無意味である。
**短さは「打ちやすさ・伝えやすさ」の基準であって、軽量性の基準ではない**。

## 3. 空き調査

### 3.1 方法

- `.jp`: JPRS WHOIS(`https://whois.jprs.jp/`)。応答に `該当するデータがありません` を含むものを未登録と判定。
- `.com`/`.net`/`.org`: レジストリ RDAP(Verisign / Public Interest Registry)。HTTP 404 を未登録と判定。
- 実施日: 2026-08-15。照会は延べ約190件(候補80語 × TLD)。

### 3.2 主要な結果

素の一般名詞はすべて押さえられており、なかでも次の2件は本件の判断に直接影響する。

| ドメイン | 状態 | 登録者(WHOIS表示) |
|---|---|---|
| `bosai.jp` | 登録済 | 国立研究開発法人防災科学技術研究所 |
| `bousai.jp` | 登録済 | 防災技術センター株式会社 |
| `keiho.jp` / `keihou.jp` | 登録済 | 民間法人・個人 |
| `moji.jp` / `sugu.jp` | 登録済 | — |

`bosai` / `bousai` の素の形は、いずれの綴りでも既に「防災の本家」と読める組織が保持している。
加えて `bosai.go.jp`(防災科研)・`bousai.go.jp`(内閣府防災)が実在するため、
**`bosai` に近い短い形を個人が取ると C1(誤認防止)に反する**。修飾語を付けた造語が必要になる。

| `karuibosai`(軽い防災) | 可 | 可 | 「軽い」が軽薄と読まれうる |

## 4. 推奨案の評価

| 基準 | `mojibosai.jp` の適合 |
|---|---|
| C1 誤認防止 | ○ 「文字」という修飾語が付くことで、公的な総称ドメインと明確に別物になる。既存の同名サービスは確認されなかった |
| C2 短さ・打ちやすさ | ○ ラベル9文字。ハイフン・数字なし。△ 「ぼうさい」の綴りに `bosai`/`bousai` の揺れがある(唯一の弱点。別名取得で緩和可能) |
| C3 本質が伝わる | ◎ README の見出し「文字だけの軽量防災情報サイト」と一対一で対応する。地図アプリではないという期待値調整にもなる |
| C4 TLD | ◎ `.jp` |
| C5 ベンダ分散 | ◎ Cloudflare Registrar は `.jp` を扱わない[^cfreg]ため、レジストラが必然的にCloudflare外になる |
| C6 中立性 | ◎ 個人名・地域名を含まない |
| C7 費用 | ○ 年約2,300〜3,900円(§8) |

`bosai` を選ぶか `bousai` を選ぶかは、本体を短くするか入力習慣に合わせるかの二択である。
本書は**本体 `mojibosai.jp`(短いほう)、別名 `mojibousai.jp`** を推す。逆でも実害はない。

## 5. 却下した案と理由

| 案 | 状態 | 却下理由 |
|---|---|---|
| `*.go.jp` | — | 登録資格が政府機関等に限られる。そもそも取得不可であり、仮に取れても N-15 に反する |
| `bosai.ne.jp` | **取得可** | `bosai.go.jp`(防災科研)と1ラベルしか違わない。C1(誤認防止)に真っ向から反する。加えて `ne.jp` の登録資格は「日本国内のネットワークサービス提供者がサービスごとに1つ」[^jprs-spec]で、個人運営サイトでの適合が自明でない |
| `bousai.ne.jp` / `bosai.or.jp` / `bousai.or.jp` | 登録済 | — (`or.jp` は法人格が必要で個人は登録不可[^jprs-spec]) |
| `ktai.jp` / `ktaibosai.jp` | 取得可 | リポジトリ名 `k-tai.bousai` とは揃うが、決定#2で「4Gケータイ対応は主目標としない」と定めた以上、**名前がポジショニングと矛盾する**。ガラケー専用サイトという誤解を招く |
| `2kb.jp` | 取得可 | ラベル3文字で最短、表記ゆれゼロ、唯一無二という強みはある。しかし ①意味が非自明で防災サイトとしての信頼感に欠ける ②**実測で地震詳細ページが既に2,454B**あり、名前が事実とずれている ③今後ページが増えれば陳腐化する |
| `karui.jp` / `tsutae.jp` | 取得可 | 単独では防災を指さない。「軽い」は語感が軽薄 |
| 新gTLD(`.site` `.online` 等) | — | 価格は安いが、`.jp`/`.com` に比べ受信側フィルタ・社内プロキシでの扱いが読みにくい(**これは実測ではなく判断**)。防災用途で到達性の不確実性を増やす理由がない |
| `.com` 単独 | — | §6 |
| 日本語ドメイン(IDN) | — | 入力が難しく、Punycode表示になる環境がある |

## 6. `.jp` を選ぶ理由(`.com` との比較)

| 観点 | `.jp` | `.com` |
|---|---|---|
| 国内向けサービスであることの表明 | ◎ | △ |
| 登録資格 | 日本国内に住所をもつ個人・団体[^jprs-spec]。個人可・本数無制限 | 制限なし |
| 失効後の悪用しにくさ | ○ 日本国内住所が必要なぶん、第三者に渡ったあとの悪用の敷居がやや高い | △ 誰でも取得可 |
| WHOIS の登録者名 | JPRS の**登録者情報非表示設定**で非表示にできる(汎用JP・都道府県型JPが対象、2014-08-18〜)[^jprs-conceal]。住所・電話は公開連絡窓口の代理公開で出さずに済む | レジストラのWHOISプライバシー(Cloudflare Registrar は無料[^cfreg]) |
| ベンダ分散(C5) | ◎ Cloudflare Registrar が非対応[^cfreg]なので、レジストラが自動的にCloudflare外になる | △ Cloudflare に寄せると レジストラ+DNS+主系ホストが同一ベンダになる |
| 年額 | 約2,300〜3,900円 | 約1,600〜2,000円 |

差額は年1,000〜2,000円で、C7 の枠内に収まる。**個人運営の非公式サイトであってもドメインの実名公開を避けられる**
点と、**レジストラが自然に分散する**点で `.jp` が優る。

## 7. 運用上の発見(構成に直結する)

### 7.1 GitHub Pages にカスタムドメインを設定すると、素のURLが消える(実測)

カスタムドメインを設定したプロジェクトサイトの `<user>.github.io/<repo>` は、301でカスタムドメインへ転送される。
2026-08-15 に実在サイトで確認した。

```
$ curl -sSI https://jekyll.github.io/jekyll/
HTTP/2 301 ... location: http://jekyllrb.com/

$ curl -sSI https://chartjs.github.io/Chart.js/
HTTP/2 301 ... location: http://www.chartjs.org/Chart.js/
```

**含意**: 副系(GitHub Pages)にカスタムドメインを設定すると、`yanai-taketo.github.io/k-tai.bousai` は
「独自ドメインへのリダイレクタ」に変わる。独自ドメインのDNSが引けない状態では、副系も道連れで開けなくなる。
**「片方が落ちても、もう片方が生きている」という現行の設計(N-8)が壊れる**。したがって副系には設定しない。

### 7.2 Cloudflare Pages の apex を使うと、DNS が Cloudflare に集約される

Cloudflare Pages で apex(`example.jp`)をカスタムドメインにする場合、
**ネームサーバをCloudflareに向けることが必須**である(サブドメインなら外部DNSでCNAMEを向けるだけでよい)[^cfpages-custom]。

**含意**: 独自ドメインを apex で使う限り、DNSはCloudflareに置くことになる。
つまり Cloudflare の広域障害時には、独自ドメイン配下は主系も副系も名前解決から落ちる。
これは §7.1 の結論(副系は独自ドメインの外に置く)を補強する。**独自ドメインを介さない生存経路を必ず1本残す**。

### 7.3 `*.pages.dev` はカスタムドメイン設定後も既定で残る

Cloudflare Pages は自動リダイレクトをしない。ドメイン不要の経路を潰したい場合のみ、自分でBulk Redirectsを設定する[^cfpages-redirect]。
本件では**潰さない**(生存経路として残す)。

### 7.4 分散状況(推奨構成)

| 層 | 主系 | 副系 |
|---|---|---|
| レジストラ | 国内レジストラ(`.jp`) | (副系はドメインを使わない) |
| DNS | Cloudflare | GitHub(`github.io`) |
| ホスティング | Cloudflare Pages | GitHub Pages |
| 生成・デプロイ | GitHub Actions(共通) | 同左 |

独自ドメイン導入後も、**ドメイン・DNSに一切依存しない経路(`yanai-taketo.github.io/k-tai.bousai`)が残る**。
ただしその経路は、ドメインが引けない状況では利用者に案内する手段がない(aboutページも読めない)。
周知は依頼者のブログ等、サイト外で行う必要がある(決定#10と整合)。

### 7.5 コード変更は不要

`generator/` に自ホストの絶対URL・`<link rel=canonical>` は存在しない(内部リンクはすべて相対/ルート相対)。
外部絶対URLは気象庁とGitHubリポジトリのみ。**ドメイン導入で生成コードの変更は生じない**。
変更が要るのは以下だけ。

- `tools/monitor.py` が読む環境変数 `SITE_URLS` に新ドメインを追加(監視対象を増やす)。
- aboutページに「予備の配信先」を1行追加することを推奨(現在は記載がなく、README にしかない)。数十バイト。

## 9. 取得後の手順(ドメイン取得を決めた場合)

1. 国内レジストラで `mojibosai.jp` を登録。**自動更新ON**、アカウントに2要素認証。
2. JPRS の登録者情報非表示設定を申請するか決める(§6)。指定事業者経由で申請[^jprs-conceal]。
3. Cloudflare にゾーンを追加し、レジストラ側のネームサーバをCloudflareのものへ変更(apex利用のため必須、§7.2)。
4. Cloudflare Pages のプロジェクトにカスタムドメイン `mojibosai.jp` と `www.mojibosai.jp` を追加(ダッシュボード経由。DNSレコードの手動追加のみでは522になる[^cfpages-custom])。
5. DNSSEC を有効化。
6. **GitHub Pages にはカスタムドメインを設定しない**(§7.1)。
7. `SITE_URLS` に新ドメインを追加。旧URL(`k-tai-bousai.pages.dev`)は監視対象に残す。
8. README の「公開中」と about ページの案内を更新。副系URLを about に1行明記する。
9. `pages.dev` からのリダイレクトは**設定しない**(生存経路として残す、§7.3)。

## 10. 依頼者に確認いただきたい点

1. **名前**: `mojibosai.jp`(文字防災)でよいか。次点は `sugubosai.jp` / `imabosai.jp` / `bosaidayori.jp`。
2. **表記ゆれ別名**: `mojibousai.jp` を追加で取得するか(年+2,300〜3,900円)。
3. **サイト名**: ドメインに合わせて表示名を「文字防災」に揃えるか、現行の呼称を維持するか。
4. **WHOIS**: 登録者名の非表示設定を使うか。
5. **レジストラ**: 更新料の総額と管理画面の使い勝手で選ぶ。お名前.comは表示価格に調整費が加算される点に注意。
6. **そもそも取得するか**: 現行の2URLのままでも機能上の不足はない。独自ドメインの効果は「覚えやすさ・伝えやすさ・将来の引き継ぎ可能性」であって、可用性や軽量性は**改善しない(むしろ§7.2の依存が増える)**。
